EASYARRANGE PROJEKT DOKUMENTACIO (AKTUALIS VERZIO)

Ez a dokumentacio a jelenlegi kodallapot alapjan keszult az EasyArrange mappa tartalma szerint:
- Frontend (React + Vite)
- Backend (Spring Boot)
- Database (MariaDB SQL dump)


1. Mi a projekt celja a program alapjan
Az EasyArrange egy szalon idopontfoglalasi es uzemeltetesi rendszer.
Celja, hogy egyetlen rendszerben kezelje:
- szolgaltatasokat,
- munkatarsakat,
- ugyfel foglalasokat,
- muszakbeosztasokat,
- valamint a staff idokizarasokat (time off / calendar block).

A rendszer tobb szerepkort tamogat:
- ADMIN
- STAFF
- CUSTOMER


2. Specifikaciok
Fobb uzleti kovetelmenyek:
- Ugyfel regisztracio, bejelentkezes, profilkezeles.
- Szolgaltatas + munkatars + datum + idosav alapu foglalas.
- Staff sajat muszakjainak kezelese.
- Staff sajat time off idoszakainak kezelese.
- Foglalasi statusz valtoztatas (BOOKED, COMPLETED, NO_SHOW, CANCELLED).
- Admin oldali user- es service-menedzsment.
- Staff-service kapcsolatok adminisztralasa.
- Utkozeskezeles foglalasok, muszakok es calendar blockok kozott.

Nem funkcionalis kovetelmenyek:
- REST API alapu backend.
- SPA frontend.
- Relacios adatbazis perzisztencia.
- Backend validacio DTO-kon keresztul.
- Egységes hibavalasz-struktura (ProblemDetail).

5. Architektura bemutatasa
A rendszer 3 retegu, kulon projektstrukturaval:

1) Frontend (React SPA)
- Oldalak route-okon keresztul:
  /, /staff, /services, /about, /contact, /booking,
  /login, /register, /profile, /profile/edit,
  /profile/change-password,
  /staff/shifts, /staff/time-off,
  /staff/bookings,
  /admin/users, /admin/services, /admin/my-staff,
  valamint wildcard route: * (NotFoundPage)
- API kommunikacio Axios klienssel.
- Server state kezeles React Query-vel.
- UI allapotkezeles UIStateContext-ben.

2) Backend (Spring Boot REST)
- Controller reteg: REST vegpontok.
- Service reteg: uzleti logika (elerheto slotok, utkozesek, statuszfrissites).
- Repository reteg: JPA adateleres.
- DTO reteg: keresi/valasz modellek.
- Exception kezeles: ProblemDetail alapu hibastruktura.

3) Database (MariaDB)
- Relacios schema FK-kal, egyedi korlatozasokkal.
- Kapcsolotablak staff-service es staff-shift kapcsolatokhoz.

11. Végpontok és metódusok
Itt a "metódus" két dolgot jelent:
- HTTP metódus (GET, POST, PUT, DELETE),
- valamint a backend oldali controller-metódus neve.

- GET /api/users -> UserRestController.getUsers() -> userService.findAll() (szűréssel)
- GET /api/users/{userId} -> UserRestController.getUser() -> userService.findUserById()
- POST /api/users/auth/login -> UserRestController.findUserForLogin() -> userService.findUserForLogin()
- POST /api/users/register -> UserRestController.addUser() -> userService.create()
- PUT /api/users/me -> UserRestController.updateUser() -> userService.update()
- PUT /api/users/admin/{userId} -> UserRestController.updateUserAsAdmin() -> userService.updateAsAdmin()
- DELETE /api/users/{userId} -> UserRestController.deleteUser() -> userService.remove()

Services:

13. Hitelesites es hibakezeles
Hitelesites:
- A backendben a HTTP Basic be van kapcsolva, de a jelenlegi SecurityConfig minden végpontot permitAll-ra állít.
- Ez azt jelenti, hogy jelen állapotban a jogosultságellenőrzés nagyrészt frontend oldali UX-korlátozásokra épül.
- A frontend localStorage-ben tárol user- és tokenadatot, de a Bearer token validáció backend oldalon jelenleg nincs teljes körűen kikényszerítve.

CORS:
- Engedelyezett originok fejlesztesben:
  - http://localhost:5173
  - http://localhost:3000

Hibakezeles:
- ProblemDetail alapu valaszok.
- Tipikus HTTP kodok: 400, 403, 404, 409, 415, 500.
- Validacios hibaknal fieldErrors/parameterErrors is visszaterhet.

15. Adatbazis sema es kapcsolatok
Kapcsolatok:
- role (1) -> (N) user
  user.role_id -> role.role_id

- user (1) -> (0..1) staff
  staff.user_id UNIQUE -> user.user_id

- staff (N) <-> (N) service a staff_service tablan keresztul
  staff_service.staff_id -> staff.staff_id
  staff_service.service_id -> service.service_id

- staff (N) <-> (N) shift a staff_shift tablan keresztul
  staff_shift.staff_id -> staff.staff_id
  staff_shift.shift_id -> shift.shift_id

- booking kapcsolatok
  booking.staff_id -> staff.staff_id
  booking.user_id -> user.user_id
  booking.service_id -> service.service_id

- calendar_block kapcsolat
  calendar_block.staff_id -> staff.staff_id

Fontosabb integritasi szabalyok:
- booking egyedi kulcs: (staff_id, start_datetime, end_datetime)
- calendar_block egyedi kulcs: (staff_id, start_datetime, end_datetime)
- shift egyedi kulcs: (day, start_shift, end_shift)
- role.name egyedi
- service.name egyedi
- user.email egyedi
